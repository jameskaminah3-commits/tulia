DO NOT HOST THE APPLICATION ON CPANEL
cPanel is built for PHP on shared Apache hosting. Running Next.js on it means Passenger or a hand-managed Node process, and in practice that gives us: no
zero-downtime deploys, no preview environments, fragile process restarts after any panel update, awkward environment-variable handling, cron limited to
minute granularity with no observability, and no straightforward rollback. Every hour saved by reusing existing hosting will be repaid several times over in
deployment incidents. If there is an existing cPanel contract, use it for the marketing page and email only.
3.1 Supabase project setup
Region: eu-central-1 (Frankfurt) or ap-south-1 (Mumbai). Mumbai typically gives lower latency to Kenya; test both with a ping before committing,
since we cannot change region later without a migration.
Two projects: wellness-staging and wellness-prod . Never develop against production.
Enable Point-in-Time Recovery on production before launch day. This is a paid add-on and it is not optional — we hold booking and payment records.
Enable pg_cron , pgcrypto , btree_gist and postgis (postgis only if we later need real geo queries; the zone table in §6 avoids it for now).
